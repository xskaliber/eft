# Xskaliber EFT 1.0.3

**Released:** 2026-10-19
**Type:** Initial release

The first general release of Xskaliber EFT on AWS Marketplace: a managed enterprise file transfer platform that runs in your own AWS account. To get started, see [Getting Started](../README.md#-getting-started) and the [tutorials](../tutorials/README.md).

## What's included

### Setup and administration

- **Guided first-run setup with no default password.** You claim a new installation with a one-time setup token from your stack's logs, then create the first System Administrator in a setup wizard. That first account keeps password sign-in as a break-glass login even when single sign-on is in use.
- **Getting Started checklist.** Tracks what a new installation needs before partners can exchange files: storage connected, SFTP server online, unique host keys, connection details to share with partners, first tenant and partner, single sign-on (optional), and subscription verified. Items tick themselves off as the system detects them.
- **Admin console** with a dashboard, tenants, users with role-based personas, an activity log, server monitoring, and context-sensitive help on every page.
- **System Settings** with a required change reason and full change history for every setting. Values that come from your CloudFormation stack are marked **Managed by deployment**.
- **Update notifications.** The console tells administrators when a newer release is available.
- **About page** showing the installed version, license terms and the open-source components included.

### File transfer

- **SFTP server** with SSH key or password authentication, running on a load-balanced, auto-scaling cluster.
- **Trading partners**, each with their own users, IP allow-lists, PGP keys and jobs.
- **Per-partner IP allow-lists** enforced by the SFTP server.
- **Unique SFTP host keys** generated for each installation, with fingerprints ready to share with partners.
- **Partner jobs** that pull from or push to partner SFTP, FTP and FTPS servers on a schedule, with retry and execution history.
- **Host key pinning** for partner SFTP servers, so files can't be redirected to an impostor server.
- **Web portal** for partner staff to view, download and upload their files.

### File processing

- PGP encryption and decryption.
- GZIP, BZIP2 and ZIP compression and decompression.
- ClamAV virus scanning, with virus definitions that update automatically every few hours.
- Lifecycle options to keep, replace or archive original files.

### Security

- Single sign-on for administrators through any OpenID Connect identity provider, with optional group-based roles and just-in-time account creation.
- Passwords of at least 12 characters with letters and numbers. Passwords set by an administrator are temporary and must be changed at next sign-in.
- Sign-in attempts limited per username.
- Deactivating a user, changing their role or resetting their password takes effect immediately.
- Stored passwords, transfer credentials, PGP private keys and passphrases are never shown again after they're saved.
- The application API isn't exposed to the internet. All browser traffic goes through the web front end.
- Every installation generates its own application secrets in AWS Secrets Manager.

### Deployment

- Launches from AWS Marketplace with a single CloudFormation template into your own AWS account. It creates the VPC (or uses yours), Aurora Serverless v2 PostgreSQL, S3 storage, ECS services, and load balancers for the web UI and SFTP.
- Three deployment sizes: `small`, `medium` and `large`.
- Optional HTTPS certificate, Route 53 alias, Multi-AZ database and CloudWatch alarm notifications.
- Database deletion protection is on by default. Your data bucket and a final database snapshot are kept when a stack is deleted.

## Requirements

- Outbound HTTPS access from the stack's private subnets for AWS services, AWS Marketplace and virus definition updates (`database.clamav.net`). A stack that creates its own VPC already has this. See [Network access](../README.md#network-access).

## Known issues

- Email notifications aren't available yet. The **SMTP/Email Configuration** settings are saved but not used.
- The password, sign-in lockout and session length values under **Security Configuration** don't change the built-in policy described in [Sign-in security](../tutorials/09-system-settings.md#sign-in-security).
